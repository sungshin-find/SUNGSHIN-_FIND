# 🔍 분실물 매칭 알고리즘 설계 (#21)

분실물(LOST) 게시물과 습득물(FOUND) 게시물을 비교해 **0~100점의 유사도 점수**를 매기는 규칙 기반 매칭입니다.
코드: `backend/posts/matching.py` · 테스트: `backend/posts/test_matching.py`

## 1. 왜 규칙 기반인가

| 방식 | 장점 | 단점 | 선택 |
|---|---|---|---|
| 머신러닝 / 임베딩 유사도 | 자유 문장도 비교 가능 | 학습 데이터 없음, 결과 설명 어려움, 서버 자원 필요 | ❌ |
| 키워드 검색 | 구현 간단 | "지갑"·"카드지갑"처럼 표현이 달라지면 못 찾음 | ❌ |
| **표준화 입력 + 규칙 기반 점수** | 결과를 "왜 매칭됐는지" 설명 가능, 가볍고 테스트하기 쉬움 | 입력을 선택지로 제한해야 함 | ✅ |

그래서 게시물 등록(#17)에서 **물건 종류 / 색상 / 장소를 자유 입력 대신 선택지**로 받도록 했습니다.

## 2. 점수 규칙 (100점 만점)

| 항목 | 조건 | 점수 |
|---|---|---|
| **물건 종류** (40) | 같은 종류 | 40 |
| | 한쪽이 '기타' | 15 |
| | 다른 종류 | **후보에서 제외** |
| **색상** (25) | 같은 색 | 25 |
| | 비슷한 계열 (예: 검정·남색·회색) | 12 |
| | 한쪽이 '기타' | 8 |
| **장소** (20) | 같은 건물 | 20 |
| | 같은 수정캠퍼스의 다른 건물 | 8 |
| | 한쪽이 '교내 야외' / '기타' | 5 |
| **날짜** (15) | 습득일 − 분실일 = 0~1일 | 15 |
| | 2~3일 | 10 |
| | 4~7일 | 5 |
| | 습득일이 분실일보다 **2일 이상 앞섬** | **후보에서 제외** |

### 가중치를 이렇게 정한 이유
- **종류 40점 (가장 큼)**: 지갑과 휴대폰은 절대 같은 물건이 될 수 없으므로 가장 강한 기준. 종류가 다르면 아예 제외합니다.
- **색상 25점**: 물건을 구분하는 두 번째로 확실한 정보. 다만 조명이나 사람마다 "검정 / 남색"처럼 다르게 부를 수 있어서 **비슷한 계열은 절반 정도(12점)** 를 줍니다.
- **장소 20점**: 분실자는 정확히 어디서 잃어버렸는지 모르는 경우가 많아서 색상보다 낮게 잡았습니다.
- **날짜 15점**: 분실물은 보통 며칠 안에 습득되지만, 늦게 발견될 수도 있어 비중을 가장 낮게 했습니다. 습득일이 분실일보다 하루 앞서는 정도는 입력 실수로 보고 허용합니다.

## 3. 기준 점수

| 기준 | 값 | 의미 |
|---|---|---|
| `MATCH_THRESHOLD` | **50점** | 이 이상이면 매칭 후보로 저장하고 "비슷한 게시물"에 표시 |
| `NOTIFY_THRESHOLD` | **70점** | 이 이상이면 양쪽 사용자에게 알림 (#22) |

- **종류만 같은 경우 = 40점** → 후보에 안 뜸 (지갑이 하나 올라올 때마다 모든 지갑 분실자에게 뜨는 걸 방지)
- **종류 + 색상만 같아도 = 65점** → 후보로 표시
- **종류 + 비슷한 색 + 같은 건물 + 2일 차이 = 82점** → 알림 대상

## 4. 동작 흐름

```
게시물 등록 / 수정
   └─ update_matches(post)
        ├─ 이 게시물의 기존 매칭 삭제
        ├─ 반대 유형 + 진행중 + (같은 종류 or 기타) 게시물만 DB에서 조회   ← 인덱스 사용
        │    (자기 글, 반환완료 글은 제외)
        ├─ 한 쌍씩 점수 계산 → 50점 이상만 Match 테이블에 저장
        └─ 새 Match 목록 반환 → #22 알림에서 70점 이상만 알림 생성
```

- `GET /api/posts/{id}/matches/` : 해당 게시물의 매칭 후보를 점수 높은 순으로, **점수 근거**와 함께 반환
  ```json
  [{ "post": {...}, "score": 82,
     "reasons": ["같은 종류 (지갑) +40", "비슷한 색상 (검정·남색) +12", "같은 장소 (성신관) +20", "날짜 차이 2일 +10"] }]
  ```
- 반환완료 처리(#23) 시 `update_matches(post)` 를 호출하면 그 게시물의 매칭이 모두 지워집니다.

## 5. 한계와 개선 아이디어
- 설명(자유 텍스트)은 점수에 반영하지 않음 → 추후 키워드 겹침 점수 추가 가능
- 건물 간 거리는 "같은 캠퍼스 여부"로만 판단 → 건물 좌표를 넣으면 거리 기반 점수로 개선 가능
- 게시물이 많아지면 등록할 때마다 계산 비용이 커짐 → 종류로 먼저 걸러서 비교 대상을 줄였고, 필요하면 비동기 작업(Celery 등)으로 분리
